`PasswordField` wraps the base `Input` component with the same `Field` layout as `TextField`, and adds a show/hide toggle button so people can check what they typed before submitting. The toggle can manage its own state, or you can control it yourself with `visible` and `onVisibleChange`.

## Accessibility

`PasswordField` connects the label, description, and error message to the input the same way `TextField` does, plus a few things specific to the toggle:

- The label uses `htmlFor`, so clicking it focuses the input.
- `aria-describedby` points to the description, but only while there's no error, so screen readers don't hear a stale description read alongside an active error.
- The error message is wired through `aria-errormessage` instead, and `aria-invalid` flips to `true` whenever `error` is set.
- The toggle button has an `aria-label` that switches between "Show password" and "Hide password", and `aria-pressed` reflects its current state. It's a real, focusable button — not `aria-hidden` like `leftSection` — since it changes what the field does.
- `autoComplete` defaults to `"current-password"`. Pass `autoComplete="new-password"` on sign-up and password-reset forms so browsers don't offer to autofill an existing saved password into a field meant for a new one.

<Callout type="info">
  `visible` and `onVisibleChange` are optional. Leave them out and `PasswordField` manages show/hide state on its own — you only need them if something outside the field also needs to know whether the password is visible.
</Callout>

## API Reference

### PasswordField

`PasswordField` accepts every native `<input>` attribute except `type`, which is fixed and switches between `"password"` and `"text"` based on the visibility state.

| Prop | Type | Default | Description |
|---|---|---|---|
| `label` | `string` | — | Label rendered above (or beside) the input. |
| `description` | `string` | — | Helper text shown below the input. Hidden automatically when `error` is set. |
| `error` | `string` | — | Validation message. Switches the field into an invalid state and renders through `FieldError`. |
| `leftSection` | `React.ReactNode` | — | Icon or element positioned inside the input, on the left. |
| `hideToggle` | `boolean` | `false` | Hides the built-in show/hide button. |
| `visible` | `boolean` | — | Controlled visibility state. Omit to let the component manage it internally. |
| `onVisibleChange` | `(visible: boolean) => void` | — | Fires whenever visibility changes, whether triggered by the toggle button or by an external `visible` update. |
| `orientation` | `"vertical" \| "horizontal" \| "responsive"` | `"vertical"` | Layout direction for the label relative to the input. |
| `fieldClassName` | `string` | — | Class name passed to the underlying `Field` wrapper. |
| `labelClassName` | `string` | — | Class name applied to the `FieldLabel`. |
| `inputClassName` | `string` | — | Class name applied to the `Input` element, merged after `className`. |
| `className` | `string` | — | Class name applied to the `Input` element. |
| `required` | `boolean` | `false` | Marks the field as required and adds the asterisk indicator. |
| `disabled` | `boolean` | `false` | Disables the input and toggle button, and dims the label. |
| `autoComplete` | `string` | `"current-password"` | Passed straight to the input. Set to `"new-password"` for sign-up and reset forms. |
