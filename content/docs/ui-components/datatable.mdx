---
title: DataTable
description: A data table with sorting, selection, column pinning, expandable rows and keyboard row navigation, plus opt-in pagination, filter toolbar and row context menus.
---

`DataTable` renders tabular data without you wiring up sorting, selection, or pagination by hand. The core wraps `Table` and `Checkbox`, and splits its internals into memoized pieces so toggling one row's selection doesn't re-render the other 500. Reach for it whenever a page needs more than a static table: bulk actions, a column pinned while the rest scrolls, or rows that expand into detail.

Features that pull in heavier primitives are separate components you compose in only when you need them: [`DataTablePagination`](#datatablepagination), [`DataTableRecordsPerPage`](#datatablerecordsperpage) (uses `Select`), the [filter toolbar](#filter-toolbar) (`DataTableSearch` uses `Input`, `DataTableFacetedFilter` uses `Popover` and `Checkbox`), [`DataTableContextMenu`](#datatablecontextmenu) (uses `ContextMenu`), and [`DataTableAction`](#datatableaction) (uses `DropdownMenu`). A table that only renders a list never ships their code: the core is about 22 KB gzipped, versus about 74 KB with every part included.

## Usage Example

<ComponentPreview path="src/registry/demos/datatable-demo.tsx" allowFullscreen>
  <DataTableDemo />
</ComponentPreview>

A minimal table needs `data` and `columns`, nothing else. Add [`sortStatus`/`onSortStatusChange`](#sorting) to make a column sortable, and render a [`DataTablePagination`](#pagination) as a child to page through results server-side or client-side:

```tsx
<DataTable data={pageData} columns={columns} idAccessor="id">
  <DataTablePagination
    page={page}
    totalRecords={total}
    recordsPerPage={recordsPerPage}
    onPageChange={setPage}
  >
    {/* optional: only add this if you want the rows-per-page select */}
    <DataTableRecordsPerPage value={recordsPerPage} onValueChange={setRecordsPerPage} />
  </DataTablePagination>
</DataTable>
```

Children of `DataTable` render below the table and read its `variant` and `fetching` state, so the pagination bar matches the table's border and disables itself while loading. The one exception is [`DataTableToolbar`](#datatabletoolbar), which renders above the table.

### Column pinning

Set [`pinned`](#datatablecolumn) to `"left"` or `"right"` on any column. Pinned columns group to their edge in the order they appear in `columns`: every `"left"` column first, every `"right"` column last. They also get a subtle shadow divider where they meet the scrolling columns. Sticky offsets come from each pinned header's rendered width, measured with `ResizeObserver`, so `width` can be a number, a string like `"20%"`, or omitted, and the offsets stay exact when content or the container resizes.

### Sticky header, scrolling body, and column footers

Set [`height`](#layout--styling) and only the `<tbody>` scrolls; the header and any pagination bar below it stay put. Add [`footer`](#datatablecolumn) to any column to render a `<tfoot>` row automatically; the example below sums a salary column across the current page.

<Callout type="warning">
  Sticky positioning needs the scrolling ancestor to be the element `DataTable` itself controls. shadcn's default `Table` component wraps the `<table>` in its own `overflow-x-auto` div, which creates a second scroll container and breaks `position: sticky` for the header. Comment out that wrapper in your `table.tsx`:

```tsx
function Table({ className, ...props }: React.ComponentProps<"table">) {
  return (
    // <div
    //   data-slot="table-container"
    //   className="relative w-full overflow-x-auto"
    // >
    <table
      data-slot="table"
      className={cn("w-full caption-bottom text-sm", className)}
      {...props}
    />
    // </div>
  );
}
```

  Only do this if you use `DataTable` with `height` set. If other tables in your app rely on the default wrapper for their own horizontal scrolling, scope this change to a variant instead of editing `table.tsx` globally.
</Callout>

### Filter toolbar

Put a [`DataTableToolbar`](#datatabletoolbar) inside `DataTable` and it renders above the table, inside the same border. Fill it with a [`DataTableSearch`](#datatablesearch), one [`DataTableFacetedFilter`](#datatablefacetedfilter) per column you want to filter by, and a [`DataTableResetFilters`](#datatableresetfilters) button. Every control is controlled, so the state can live anywhere: in React state, in the URL, or in a request to your API.

For client-side data, [`useDataTableFilters`](#usedatatablefilters) holds that state for you and hands back `filteredData`, plus per-option counts for the facet popovers. Search is a case-insensitive "contains" on the fields you list. Facets combine with AND, and the values picked inside one facet combine with OR, so "Role: admin, editor" + "Status: active" means active admins or editors.

<ComponentPreview path="src/registry/demos/datatable-filter-toolbar-demo.tsx" allowFullscreen>
  <DataTableFilterToolbarDemo />
</ComponentPreview>

```tsx
const filters = useDataTableFilters(members, {
  search: ["name", "email"],
  facets: { role: "role", status: "status" }, // or (m) => m.tags for arrays
});

<DataTable data={filters.filteredData} columns={columns} idAccessor="id">
  <DataTableToolbar actions={<Button size="sm">Invite</Button>}>
    <DataTableSearch value={filters.search} onValueChange={filters.setSearch} />
    <DataTableFacetedFilter
      title="Role"
      options={roleOptions}
      value={filters.getFacetValue("role")}
      onValueChange={(v) => filters.setFacetValue("role", v)}
      counts={filters.getFacetCounts("role")}
    />
    <DataTableResetFilters visible={filters.isFiltered} onReset={filters.reset} />
  </DataTableToolbar>
</DataTable>
```

Filtering on the server instead? Skip the hook, keep `search` and the facet values in your own state, and send them with the request. Pass `debounceMs` to `DataTableSearch` so you don't fire one request per keystroke. When you paginate, set the page back to 1 whenever a filter changes, as the demo does.

### Keyboard navigation

Set [`keyboardNavigation`](#row-interaction) to let people move through rows with the keyboard. The table body becomes a single Tab stop (a roving `tabIndex`): Tab lands on the last focused row, the arrow keys move between rows, and Tab again leaves the table. Clicking a row also moves the cursor there.

<ComponentPreview path="src/registry/demos/datatable-keyboard-demo.tsx" allowFullscreen>
  <DataTableKeyboardDemo />
</ComponentPreview>

| Key | Action |
|---|---|
| `↓` / `↑` | Next / previous row |
| `Home` / `End` | First / last row |
| `PageDown` / `PageUp` | Jump by about one screen of rows |
| `Enter` | Same as clicking the row: calls `onRowClick`, and toggles expansion when `expandOnRowClick` is on (or when there's no `onRowClick`) |
| `Space` | Toggle the row's selection; `Shift+Space` selects the range from the last toggled row |
| `→` / `←` | Expand / collapse the row |
| `Ctrl+A` / `⌘A` | Select every row on the page |

Keys only count when the row itself has focus. A button, input or checkbox inside a cell keeps its own keys, so an arrow press in an inline input moves the caret, not the row. With `height` set, the focused row is scrolled clear of the sticky header and footer. `onActiveRowChange` tells you which row has focus, for example to show a preview panel next to the table.

### Expandable rows

Pass [`renderRowSubContent`](#expansion) to add a chevron toggle column. It's called lazily, only for rows that are open, so heavy detail content doesn't slow down rows that stay collapsed.

<ComponentPreview path="src/registry/demos/datatable-expandable-demo.tsx" allowFullscreen>
  <DataTableExpandableDemo />
</ComponentPreview>

A few props extend this without changing `renderRowSubContent` itself:

- `singleExpand` collapses any other open row when one expands, for accordion-style behavior.
- `rowExpandable` hides the toggle on rows that shouldn't expand at all.
- `expandedRecordIds` and `onExpandedRecordIdsChange` move expansion state outside the table, for cases like "expand this row" from a search result.

### Row actions: context menu and action button

Wrap the table in [`DataTableContextMenu`](#datatablecontextmenu) for a right-click menu, and use [`DataTableAction`](#datatableaction) in a column for a visible "kebab" button. Both take a [`RowContextMenuItem[]`](#rowcontextmenuitem): the same shape, so one function can back both at once.

```tsx
<DataTableContextMenu items={getRowActions}>
  <DataTable data={rows} columns={columns} idAccessor="id" />
</DataTableContextMenu>
```

### Refs and scroll shadows

The [ref props](#refs), `headerRef`, `bodyRef`, `tableRef`, and `scrollViewportRef`, expose the underlying DOM nodes; `rowRef` fires for every row's `<tr>` as rows mount and unmount. The table also tracks its own scroll position and fades in a shadow on whichever edge still has hidden columns. That's useful feedback once you're pinning columns on a table wider than its container.

## Accessibility

- The header "select all" checkbox exposes a real mixed state through the `Checkbox` primitive. Screen readers announce the mixed state correctly because it comes from the primitive, not a faked `aria-checked` value.
- Every checkbox carries its own `aria-label`: `"Select all records"` on the header, `"Select record N"` per row.
- Sort toggles and the expand chevron are real `<button>` elements. They're keyboard-focusable and respond to Enter and Space without extra wiring. The sort direction icons (`ArrowUp`/`ArrowDown`/`ChevronsUpDown`) are purely visual.
- `DataTableContextMenu` and the `DataTableAction` dropdown both render through shadcn's menu primitives, which handle roving focus, arrow-key navigation, `Escape` to close, and correct `role="menu"`/`role="menuitem"` semantics without any extra work on your side.
- The loading overlay (`fetching`) is visual only. It doesn't announce anything to assistive tech. Wire up your own `aria-live` region around the table if that matters for your users.
- A row itself (the `<tr>`) is clickable via `onRowClick` or `expandOnRowClick`, but a table row isn't a native interactive element. By default it's not keyboard-focusable. Turn on [`keyboardNavigation`](#keyboard-navigation) to make rows focusable with a roving `tabIndex` (one Tab stop for the whole body), with `Enter` acting as the row click and a visible focus ring. Expandable rows then also expose `aria-expanded`. Screen readers still won't announce a row as a button, so if a row click is the only way to reach some functionality, keep a real button for it too (the expand chevron, a `DataTableAction` item).
- `DataTableToolbar` is a `role="group"` labelled "Table filters". `DataTableSearch` is a `type="search"` input with an `aria-label` (default `"Search records"`), a labelled clear button, and `Escape` to clear.
- `DataTableFacetedFilter`'s trigger announces how many values are selected (e.g. "Role: 2 selected"). Inside the popover, options are real checkboxes in a labelled group; `↑`/`↓`/`Home`/`End` move between them and `Space` toggles. The popover primitive handles focus trapping and `Escape`.

## API Reference

### DataTable

`DataTable<T>` is generic over your record type. Props are grouped below by what they control.

#### Data & columns

| Prop | Type | Default | Description |
|---|---|---|---|
| `data` | `T[]` | — | Records to render. Slice this yourself for pagination; the table renders exactly what you pass in. |
| `columns` | `DataTableColumn<T>[]` | — | Column definitions. See [DataTableColumn](#datatablecolumn). |
| `idAccessor` | `keyof T \| ((record: T) => React.Key)` | `JSON.stringify(record)` | Extracts a stable id per row. Set this for selection and expansion to survive re-sorts and re-fetches. The JSON fallback works but is slower, and it breaks if field order changes. |
| `noRecordsText` | `string` | `"No records to show"` | Message shown when `data` is empty and `fetching` is false. |

#### Sorting

| Prop | Type | Default | Description |
|---|---|---|---|
| `sortStatus` | `SortStatus<T>` | — | Current sort column and direction. |
| `onSortStatusChange` | `(status: SortStatus<T>) => void` | — | Called when a sortable column header is clicked. Sorting `data` itself is on you: pass the already-sorted slice back in. |

<Callout type="info">
  TypeScript requires `sortStatus`/`onSortStatusChange` only when at least one column has `sortable: true`, and only if `columns` is inferred rather than pre-typed. Annotate a separate `columns` array with `satisfies DataTableColumn<T>[]` instead of `: DataTableColumn<T>[]` to keep that check working.
</Callout>

#### Selection

| Prop | Type | Default | Description |
|---|---|---|---|
| `selectedRecords` | `T[]` | — | Currently selected records. |
| `onSelectedRecordsChange` | `(records: T[]) => void` | — | Providing this enables the checkbox column, the header "select all" control, and shift-click range selection. |

#### Row interaction

| Prop | Type | Default | Description |
|---|---|---|---|
| `onRowClick` | `(record: T, rowIndex: number) => void` | — | Called when a row is clicked. Fires alongside expand-on-click if `renderRowSubContent` is set. |
| `highlightOnHover` | `boolean` | `true` | Adds a hover background to rows. |
| `keyboardNavigation` | `boolean` | `false` | Makes rows focusable with a roving `tabIndex` and adds arrow-key navigation. See [Keyboard navigation](#keyboard-navigation) for every key. |
| `onActiveRowChange` | `(record: T, rowIndex: number) => void` | — | Called when the focused row changes under `keyboardNavigation`, by keyboard or by click. |

#### Expansion

| Prop | Type | Default | Description |
|---|---|---|---|
| `renderRowSubContent` | `(record: T, rowIndex: number) => React.ReactNode` | — | Providing this enables expandable rows and adds the chevron toggle column. Called only for rows that are open. |
| `rowExpandable` | `(record: T, rowIndex: number) => boolean` | every row expandable | Hides the toggle on rows that shouldn't expand. |
| `expandOnRowClick` | `boolean` | `true` | Clicking anywhere on the row toggles expansion, not just the chevron. |
| `singleExpand` | `boolean` | `false` | Expanding a row collapses any other open row. |
| `expandedRecordIds` | `React.Key[]` | — | Controlled set of expanded row ids. Omit to let the table manage expansion itself. |
| `onExpandedRecordIdsChange` | `(ids: React.Key[]) => void` | — | Required alongside `expandedRecordIds` for controlled expansion. |

#### Pagination

| Prop | Type | Default | Description |
|---|---|---|---|
| `children` | `React.ReactNode` | — | Rendered below the table, e.g. [`DataTablePagination`](#datatablepagination). A [`DataTableToolbar`](#datatabletoolbar) child renders above it instead. Children read the table's `variant` and `fetching` through context. |

#### Layout & styling

| Prop | Type | Default | Description |
|---|---|---|---|
| `fetching` | `boolean` | `false` | Shows a loading overlay over the current rows. |
| `height` | `number` | — | Fixed pixel height. Only the body scrolls; see the [sticky example](#sticky-header-scrolling-body-and-column-footers) for the required `Table` change. |
| `variant` | `"bordered" \| "borderless"` | `"bordered"` | `"bordered"` shows the outer box border and a divider under the header and every row. `"borderless"` removes both. |
| `className` | `string` | — | Class applied to the table's outer wrapper. |
| `rowClassName` | `string \| ((record: T, rowIndex: number) => string \| undefined)` | — | Class for every row, or a function to style specific rows conditionally. |
| `rowStyle` | `React.CSSProperties \| ((record: T, rowIndex: number) => React.CSSProperties \| undefined)` | — | Same as `rowClassName`, for inline styles. |
| `headerClassName` | `string` | — | Class applied to the header row, on top of each column's own `className`. |
| `headerStyle` | `React.CSSProperties` | — | Inline style for the header row. |

#### Refs

| Prop | Type | Default | Description |
|---|---|---|---|
| `headerRef` | `React.Ref<HTMLTableSectionElement>` | — | Ref to the `<thead>`. |
| `bodyRef` | `React.Ref<HTMLTableSectionElement>` | — | Ref to the `<tbody>`. |
| `tableRef` | `React.Ref<HTMLTableElement>` | — | Ref to the `<table>` element. |
| `scrollViewportRef` | `React.Ref<HTMLDivElement>` | — | Ref to the scrolling container — the same element the table watches for scroll shadows. |
| `rowRef` | `(element: HTMLTableRowElement \| null, record: T, rowIndex: number) => void` | — | Called for every row's `<tr>` as rows mount and unmount. |

| `className` | `string` | — | Class applied to both the `<th>` and every `<td>` in this column. |
| `style` | `React.CSSProperties` | — | Inline style applied to both the `<th>` and every `<td>`. |

#### RowContextMenuItem

| Prop | Type | Default | Description |
|---|---|---|---|
| `key` | `string` | — | Unique key for the item. |
| `label` | `React.ReactNode` | — | Item content. |
| `onClick` | `() => void` | — | Called when the item is selected. |
| `icon` | `React.ReactNode` | — | Icon rendered before the label. |

| `disabled` | `boolean` | `false` | Disables the item. |

## DataTablePagination

An opt-in pagination bar. Render it as a child of `DataTable`. It only uses `Button`, so adding it costs about 2 KB gzipped.

| Prop | Type | Default | Description |
|---|---|---|---|
| `page` | `number` | — | Current page, 1-indexed. |
| `totalRecords` | `number` | — | Total record count across all pages. |
| `recordsPerPage` | `number` | — | Records shown per page. |
| `onPageChange` | `(page: number) => void` | — | Called when a page control is clicked. |
| `renderInfo` | `(info) => React.ReactNode` | `"Showing X–Y of Z"` | Custom info text. `info` is `{ from, to, totalRecords, page, totalPages }`. |
| `siblingCount` | `number` | `1` | Page numbers shown on each side of the current page before collapsing into "…". |
| `disabled` | `boolean` | table's `fetching` | Disables every page control. |
| `children` | `React.ReactNode` | — | Extra controls next to the page buttons, e.g. `DataTableRecordsPerPage`. |
| `className` | `string` | — | Class applied to the bar's wrapping `<div>`. |
| `ref` | `React.Ref<HTMLDivElement>` | — | Ref to the bar's wrapping `<div>`. Replaces the old `footerRef` prop. |

## DataTableRecordsPerPage

A "Rows per page" select, placed inside `DataTablePagination`. It's a separate component because it brings in `Select`, the single heaviest part of the old pagination bar (about 40 KB gzipped).

| Prop | Type | Default | Description |
|---|---|---|---|
| `value` | `number` | — | Current records per page. |
| `onValueChange` | `(recordsPerPage: number) => void` | — | Called when an option is picked. |
| `options` | `number[]` | `[10, 25, 50, 100]` | Options in the select. |
| `label` | `React.ReactNode` | `"Rows per page"` | Text before the select. Pass `null` to hide it. |
| `disabled` | `boolean` | table's `fetching` | Disables the select. |
| `className` | `string` | — | Class applied to the wrapping `<div>`. |

## DataTableContextMenu

Wraps a `DataTable` and gives its rows a right-click (or long-press) menu. The whole table shares **one** menu: rows only report which record was clicked, and `items` runs for that row when the menu opens, never during render. A table with 1,000 rows still mounts a single menu, and per-row conditions always see the row's current data.

```tsx
const getRowActions = (user: User) => {
  if (user.status === "deleted") return undefined; // native browser menu on this row
  return [
    { key: "edit", label: "Edit", disabled: !canEdit(user), onClick: () => edit(user) },
    { key: "delete", label: "Delete", danger: true, onClick: () => remove(user) },
  ];
};
```

| Prop | Type | Default | Description |
|---|---|---|---|
| `items` | `(record: T, rowIndex: number) => RowContextMenuItem[] \| undefined` | — | Menu items for the right-clicked row, called when the menu opens. Return `undefined` or `[]` to keep the browser's native menu on that row. Async checks (e.g. permissions from the server) should be loaded with the data beforehand. |
| `children` | `React.ReactNode` | — | The `DataTable` to wrap. |

### Migrating from `pagination`, `rowContextMenu`, and `footerRef`

| Before | After |
|---|---|
| `pagination={{ page, totalRecords, recordsPerPage, onPageChange }}` | `<DataTablePagination page={page} totalRecords={totalRecords} recordsPerPage={recordsPerPage} onPageChange={onPageChange} />` as a child of `DataTable` |
| `pagination.onRecordsPerPageChange` / `recordsPerPageOptions` | `<DataTableRecordsPerPage value={recordsPerPage} onValueChange={...} options={...} />` inside `DataTablePagination` |
| `rowContextMenu={getActions}` | wrap the table: `<DataTableContextMenu items={getActions}>…</DataTableContextMenu>` |
| `footerRef={ref}` | `ref={ref}` on `DataTablePagination` |

### DataTableSearch

A search input with a search icon and a clear button. It accepts every `<input>` prop except `value`, `defaultValue`, `onChange` and `type`.

| Prop | Type | Default | Description |
|---|---|---|---|
| `value` | `string` | — | Current query. |
| `onValueChange` | `(value: string) => void` | — | Called with the new query. Clearing (button or `Escape`) calls it right away, even with `debounceMs`. |
| `debounceMs` | `number` | `0` | Waits this long after the last keystroke before calling `onValueChange`. |
| `placeholder` | `string` | `"Search…"` | Input placeholder. |
| `aria-label` | `string` | `"Search records"` | Accessible name of the input. |
| `className` | `string` | — | Class applied to the `<input>`. |
| `wrapperClassName` | `string` | — | Class applied to the wrapping `<div>` (default width `sm:w-64`). |

### DataTableFacetedFilter

A dashed button that opens a popover with one checkbox per option. The selected values show as badges on the button, collapsing to "N selected" past `maxBadges`.

| Prop | Type | Default | Description |
|---|---|---|---|
| `title` | `string` | — | Button label, and the accessible name of the option group. |
| `options` | `DataTableFacetOption[]` | — | `{ value: string; label: ReactNode; icon?: ReactNode; keywords?: string }`. `keywords` is what the option search matches; it defaults to `label` when that's a string. |
| `value` | `string[]` | — | Selected option values. `onValueChange` always returns them in `options` order. |
| `onValueChange` | `(value: string[]) => void` | — | Called when an option is toggled or "Clear filter" is clicked. |
| `counts` | `Map<string, number> \| Record<string, number>` | — | Row count shown next to each option. `useDataTableFilters().getFacetCounts(facet)` returns the right shape. |
| `searchable` | `boolean` | `options.length > 7` | Shows a search box above the options. |
| `maxBadges` | `number` | `2` | Most selected labels shown on the button. |
| `icon` | `React.ReactNode` | a plus-circle icon | Icon before the title. |
| `disabled` | `boolean` | `false` | Disables the trigger. |
| `align` | `"start" \| "center" \| "end"` | `"start"` | Popover alignment relative to the button. |
| `className` | `string` | — | Class applied to the trigger button. |

### DataTableResetFilters

A ghost "Reset ×" button. It takes every `Button` prop except `onClick`.

| Prop | Type | Default | Description |
|---|---|---|---|
| `onReset` | `() => void` | — | Called on click. |
| `visible` | `boolean` | `true` | Renders nothing when `false`. Pass `isFiltered` to show it only while a filter is active. |
| `children` | `React.ReactNode` | `"Reset"` | Button label. |

### useDataTableFilters

```ts
const filters = useDataTableFilters(data, {
  search: ["name", "email"],          // or (record, query) => boolean
  facets: { role: "role", tags: (r) => r.tags },
  initialSearch: "",                  // optional, e.g. from the URL
  initialFacetValues: { role: ["admin"] },
});
```

A facet accessor is a field name or a function. If it returns an array, a row matches when any item is selected. Values are compared as strings.

| Returns | Type | Description |
|---|---|---|
| `filteredData` | `T[]` | `data` with the search and every facet applied. The same array as `data` when nothing is filtered. |
| `search` / `setSearch` | `string` / `(search: string) => void` | Search query. |
| `facetValues` | `Partial<Record<F, string[]>>` | Every facet's selected values. |
| `getFacetValue` | `(facet: F) => string[]` | Selected values of one facet, `[]` if none. |
| `setFacetValue` | `(facet: F, values: string[]) => void` | Replaces one facet's selection. |
| `getFacetCounts` | `(facet: F) => Map<string, number>` | Rows per value, counting rows that pass the search and every *other* facet, so picking one value doesn't hide the others' counts. |
| `isFiltered` | `boolean` | `true` while the search or any facet is active. |
| `reset` | `() => void` | Clears the search and every facet. |

The pure helpers behind it, `filterRecords(data, state, options)` and `getFacetCounts(data, facet, state, options)`, are exported too, for filtering outside React (in a loader or on the server).

## DataTableAction

A "kebab" button, three dots that open a dropdown menu on click, is meant for an actions column. It takes the same `RowContextMenuItem[]` shape as `DataTableContextMenu`, so a table can share one list of actions between a right-click menu and a visible button, as shown in [Row actions](#row-actions-context-menu-and-action-button).

### Usage Example

<ComponentPreview path="src/registry/demos/datatable-action-standalone-demo.tsx" allowFullscreen>
  <DataTableActionStandaloneDemo />
</ComponentPreview>

It stops click propagation on its own, so it's safe to drop into a row that also has `onRowClick` or `expandOnRowClick` without accidentally triggering those.

### API Reference

| Prop | Type | Default | Description |
|---|---|---|---|
| `items` | `RowContextMenuItem[]` | — | Menu items. The button renders nothing if this is empty. |
| `label` | `string` | `"Open menu"` | Accessible label for the trigger button. |
| `icon` | `React.ReactNode` | a 3-dot icon | Icon shown on the trigger button. |
| `className` | `string` | — | Class applied to the trigger button. |
| `align` | `"start" \| "center" \| "end"` | `"end"` | Menu alignment relative to the trigger. |
| `side` | `"top" \| "bottom" \| "left" \| "right"` | `"bottom"` | Which side of the trigger the menu opens on. |

## Utilities

Two helpers from `utils.ts` handle row numbering, exported alongside the components:

```tsx
// Pure function, if you're computing the number inside a custom `render`:
getSequenceNumber(rowIndex, page, recordsPerPage); // 1, 2, 3... continuing across pages

// Ready-made column: drop it straight into `columns`:
columns={[
  createSequenceColumn({ page, recordsPerPage }), // omit page/recordsPerPage outside pagination
  ...restOfYourColumns,
]}
```

`createSequenceColumn` also accepts `title` (default `"No."`), `width` (default `56`), `pinned`, and `accessor` (default `"__sequence"`, in case that name collides with a real field on `T`).
